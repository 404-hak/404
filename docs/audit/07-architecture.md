# Архитектура и структура

## Как устроено сейчас

```
 Буй (гидрофон)                 Сервер (один процесс FastAPI)                       Дежурный
 ─────────────                 ─────────────────────────────                       ────────
 POST /api/buoys/{id}/audio ──▶ dsp.read_wav → нейросеть (NumPy) → решение      ┌─▶ браузер: React (карта Leaflet/Яндекс/3D,
 POST …/heartbeat          ──▶ World: буи, тревоги + цепочка SHA-256 ── WS /ws ─┤    лист разделов, тревоги, улики)
                                SQLite (WAL) + data/clips/*.wav                    └─▶ iPhone: то же в WKWebView (ios/)
                                Sim (симулятор/демо), погода Open-Meteo
                                Отдаёт и собранный сайт (web/dist)
```

Структура репозитория: `api/` (сервер, тесты), `web/` (сайт), `ios/` (обёртка XcodeGen), `brand/` (знак, токены цветов, брендбук),
`tools/` (геоданные дельты, обучение нейросети), `scripts/` (запуск), `.devcontainer/` (Codespaces), `docs/audit/` (этот аудит).

## Оценка

| ID | Уровень | Что | Статус |
|----|---------|-----|--------|
| A1 | ✓ | Один процесс и SQLite — правильно для пилота на 10–50 буёв: просто развернуть, нечему ломаться. | — |
| A2 | P1 | Буи и дежурные ходят в один и тот же API на одном адресе. Буи — это «железо в поле», им нужен свой узкий вход: свой токен на буй, только два адреса, ограничение частоты; лучше — отдельный порт/домен или VPN. | ⏳ |
| A3 | P1 | Живые данные — полный снимок состояния каждые 5 с по WebSocket. На 10 буёв это нормально; на сотни — рассылать события (новая тревога, буй изменился). | ⏳ см. 03-performance F7 |
| A4 | P1 | Демо/симуляция переплетены с рабочей логикой (`World.reset` сеет историю, `Sim` двигает буи). | 🟡 `DEMO=0` ✅; ⏳ демо — отдельный режим с отдельной базой |
| A5 | P2 | Доказательная часть (цепочка, улики) — внутри общего объекта `World`. Для суда её лучше выделить: неизменяемый журнал событий (append-only), подпись записей, внешняя «якорная» публикация хэша. | ⏳ см. 01-security S13 |
| A6 | P2 | Фронтенд: два слоя вне React (`upkMotion.ts`, `upkUi.ts`) правят DOM напрямую — быстро, но их состояние не видно React и не проверяется тестами. | ⏳ держать их маленькими, покрыть e2e-сценариями |
| A7 | P2 | Корневого `.gitignore` нет (есть в `api/`, `web/`, `ios/`, `brand/`). | ⏳ общий `.gitignore` (`.DS_Store`, `*.log`, `.env`) |
| A8 | P3 | Веса нейросети `api/app/audio/model.npz` лежат в git — при росте моделей нужен Git LFS или выпуск (Release) с весами. | ⏳ |

## Куда расти (по шагам)

1. **Пилот (сейчас):** один сервер, `ACCESS_TOKEN`, `DEMO=0`, HTTPS, резервные копии — см. 08-infrastructure.
2. **Несколько участков:** учётные записи и роли; отдельный вход для буёв; события вместо снимков; Postgres вместо SQLite.
3. **Ведомственная система:** журнал улик с подписями, интеграция с ведомственными системами учёта нарушений, SSO.
