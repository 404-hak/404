# Безопасность

Проверено: код API (`api/app/*`), сборка и отдача фронтенда, WebSocket, зависимости (`pip-audit`, `npm audit`), приложение iOS, CI.
Шкала: **P0** — критично, чинить до любого показа вне команды; **P1** — высокий; **P2** — средний; **P3** — низкий.
Статус: ✅ исправлено в ветке `main` · 🟡 частично · ⏳ не сделано.

## Модель угроз (коротко)

Система подсказывает инспектору, где браконьер. Значит, главный противник — сам браконьер и его помощники. Им интересно:
1. видеть, где катер инспектора и где стоят буи (обходить сеть);
2. закрывать или подделывать тревоги (отвлечь катер в другой сектор);
3. стереть или подменить улики (звук, цепочку SHA-256);
4. «заглушить» буй — притвориться, что он на связи, когда он молчит;
5. положить сервер в нужную ночь (DoS).

Сейчас почти всё это возможно с одного адреса сайта — см. S1–S5.

## Что сделано в этом проходе (S1, S2, S6, S9, S10)

Новый вход без лишнего интерфейса — **ссылка доступа**:

- Задать на сервере `ACCESS_TOKEN=<длинная случайная строка>` (например, `python -c "import secrets;print(secrets.token_urlsafe(32))"`).
- Дежурному отправить ссылку `https://<сервер>/?access=<токен>` — сервер поставит cookie `HttpOnly; SameSite=Strict` (и `Secure` по HTTPS) на 30 дней и уберёт токен из адресной строки.
- Программы и буи: заголовок `Authorization: Bearer <ACCESS_TOKEN>` (буи по-прежнему могут иметь свой `BUOY_TOKEN` только на свои два адреса).
- Без `ACCESS_TOKEN` всё работает как раньше (режим показа), но в журнал при старте пишется предупреждение.
- `DEMO=0` выключает `/api/demo/*` — **на настоящих данных обязательно**: иначе кнопка «Сбросить» стирает улики.
- В приложении iOS адрес сервера можно задать уже со ссылкой доступа.

Дальше по-хорошему (⏳): учётные записи и роли (дежурный / старший / наблюдатель), журнал действий, вход через SSO ведомства, ограничение частоты запросов, отдельный сетевой контур для буёв.
